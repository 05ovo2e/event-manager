# 모임 이벤트 관리 웹 MVP PRD

## 1. 개요

### 1.1 문제 정의

다양한 모임을 진행하는 주최자는 공지, 참여자 관리 등 많은 일을 직접 처리해야 한다. 이 과정이 메신저와 메모에 흩어져 있어 정보 누락과 반복 안내가 발생한다.

### 1.2 제품 비전

모임 주최자가 한 페이지에서 모임 정보를 만들고, 초대 링크로 참여자를 모으고, 공지를 전달할 수 있는 웹 서비스를 제공한다.

### 1.3 타깃 사용자

- 1차 타깃: 일회성 친구 모임을 주최하는 사람 (회식, 번개, 여행 등 단발 이벤트)
- 참여자: 주최자가 공유한 초대 링크로 들어오는 모임 구성원

## 2. 목표와 성공 지표

### 2.1 목표

- 주최자가 모임을 만들고 참여자에게 공유하기까지 5분 이내에 완료할 수 있다.
- 공지가 한 곳에 모여 참여자가 정보를 찾기 쉽다.

## 3. 범위

### 3.1 MVP 포함

- 구글 로그인
- 모임 생성, 수정, 삭제 (주최자만)
- 초대 링크 생성과 복사
- 초대 링크로 진입 시 자동 참여자 등록
- 내 모임 목록 (주최한 모임, 참여한 모임)
- 공지 작성, 수정, 삭제, 목록 조회 (주최자만 작성)

### 3.2 MVP 제외 (추후 구현)

- 참석 관리: 참석, 불참, 미정 응답, 정원 관리, 대기자 목록
- 정산 (비용 입력, 1인당 금액 계산, 송금 여부 확인)
- 정기 모임 반복 일정
- 결제 서비스 연동

## 4. 사용자 흐름

### 4.1 주최자 흐름

1. 구글 로그인
2. 대시보드에서 "모임 만들기" 선택
3. 제목, 일시, 장소, 설명 입력 후 저장
4. 모임 상세에서 초대 링크 복사
5. 단체 메신저 등으로 초대 링크 공유
6. 모임 상세에서 공지 작성

### 4.2 참여자 흐름

1. 주최자가 공유한 초대 링크 접속
2. 구글 로그인 (미로그인 상태인 경우)
3. 자동 참여 처리 후 모임 상세로 이동
4. 공지와 모임 정보 확인

## 5. 기능 요구사항

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| F-01 | 구글 로그인 | 기존 구현을 재사용한다. 로그인 후 대시보드로 이동한다. | 필수 |
| F-02 | 모임 생성 | 제목, 일시, 장소, 설명을 입력한다. 제목과 일시는 필수다. | 필수 |
| F-03 | 모임 수정 | 주최자만 정보를 수정할 수 있다. | 필수 |
| F-04 | 모임 삭제 | 주최자만 삭제할 수 있다. 삭제 전 확인 창을 띄운다. | 필수 |
| F-05 | 초대 링크 | 추측이 어려운 토큰을 포함한 링크를 생성하고 복사한다. | 필수 |
| F-06 | 초대 참여 | 링크로 진입하면 참여자로 등록한다. 이미 참여한 경우 중복 등록하지 않는다. | 필수 |
| F-07 | 내 모임 목록 | 주최한 모임과 참여한 모임을 구분해 보여준다. | 필수 |
| F-08 | 공지 작성 | 주최자만 공지를 작성한다. 내용은 필수다. | 필수 |
| F-09 | 공지 수정과 삭제 | 주최자만 자신이 작성한 공지를 수정하거나 삭제할 수 있다. | 필수 |
| F-10 | 공지 목록 | 모임 상세에서 최신순으로 공지를 보여준다. | 필수 |
| F-11 | 공지 상단 고정 | 중요한 공지를 목록 상단에 고정한다. | 선택 |

## 7. 데이터 모델

기존 `public.profiles` 테이블을 재사용한다. `profiles`는 `auth.users`와 1:1로 연결되어 있다.

### 7.1 events

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | uuid | 기본 키 |
| host_id | uuid | 주최자, `profiles.id` 참조 |
| title | text | 모임 제목, 필수 |
| description | text | 모임 설명 |
| starts_at | timestamptz | 모임 일시, 필수 |
| location | text | 장소 |
| invite_token | text | 초대 토큰, unique |
| created_at | timestamptz | 생성 시각 |

### 7.2 event_members

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| event_id | uuid | `events.id` 참조 |
| user_id | uuid | `profiles.id` 참조 |
| joined_at | timestamptz | 참여 시각 |

기본 키는 `(event_id, user_id)` 복합 키다.

### 7.3 announcements

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | uuid | 기본 키 |
| event_id | uuid | `events.id` 참조 |
| author_id | uuid | 작성자, `profiles.id` 참조 |
| content | text | 공지 내용, 필수 |
| is_pinned | boolean | 상단 고정 여부, 기본값 false |
| created_at | timestamptz | 작성 시각 |

## 8. 보안과 권한

### 8.1 RLS 방침

- `events`: 해당 모임의 멤버만 조회 가능. 생성은 본인이 host_id인 경우만 가능. 수정과 삭제는 주최자만 가능.
- `event_members`: 본인 행만 생성 가능 (초대 함수를 통해서만 등록). 같은 모임 멤버끼리 목록 조회 가능.
- `announcements`: 해당 모임의 멤버만 조회 가능. 작성, 수정, 삭제는 주최자만 가능.
- 기존 `profiles` 정책과 `anon` 권한 회수 방침을 유지한다.

### 8.2 초대 토큰 처리

- 모임 정보는 토큰 없이 조회할 수 없어야 한다.
- 토큰 검증과 참여 등록은 security definer 함수로 처리한다. 클라이언트가 `event_members`에 직접 insert하도록 허용하지 않는다.
- 토큰은 추측이 어렵도록 충분한 길이의 난수로 생성한다.

### 8.3 기존 코드 이슈 (함께 수정)

- `app/auth/confirm/route.ts`의 `next` 값은 검증 없이 redirect에 사용된다. 외부 사이트로 이동할 수 있는 open redirect 위험이 있으므로 같은 사이트 경로만 허용하도록 수정한다.
- 같은 파일의 에러 메시지는 인코딩 없이 쿼리에 붙는다. `encodeURIComponent`로 처리한다.
- `/invite` 경로는 proxy의 허용 경로에 포함하여 비로그인 상태에서도 로그인 안내 후 돌아올 수 있게 한다. 허용 여부와 방식은 구현 단계에서 확정한다.

## 9. 예외 케이스

| 상황 | 처리 |
| --- | --- |
| 비로그인 사용자가 `/protected` 접근 | 로그인 화면으로 이동 |
| 비로그인 사용자가 초대 링크 접근 | 로그인 후 같은 초대 링크로 복귀 |
| 잘못되거나 존재하지 않는 초대 토큰 | 안내 문구와 대시보드 이동 버튼 표시 |
| 이미 참여한 사용자가 같은 초대 링크 재접속 | 중복 등록 없이 모임 상세로 이동 |
| 참여자가 다른 모임 상세에 직접 URL로 접근 | 권한 없음 안내 후 대시보드로 이동 |
| 참여자가 공지 작성 시도 | 버튼 비노출, 서버에서도 거부 |
| 모임 삭제 | 확인 창 표시, 삭제 시 연결된 참여자와 공지도 함께 삭제 (cascade) |
| 모임 제목 또는 일시 누락 | 폼 검증 메시지 표시, 저장하지 않음 |
| 공지 내용 빈 값 | 저장하지 않음 |

## 10. 개발 단계

1. 범위 확정과 사용자 흐름 정의 (완료)
2. PRD 작성 (본 문서)
3. DB 스키마와 RLS 설계, 마이그레이션 적용
4. 인증 연동 점검, 모임 생성과 목록 구현
5. 초대 링크와 참여자 등록 구현
6. 공지 기능 구현
7. 점검: `npm run check`, Supabase 보안 어드바이저, 권한별 수동 시나리오 테스트

## 11. 오픈 이슈

- 초대 토큰 만료 정책: 무기한 유효할지, 모임 일시 이후 만료할지 결정 필요
- 참여자 탈퇴 기능 포함 여부 (MVP 포함 시 F-12로 추가)
- 주최자 권한 양도 여부
- 모임 일시가 지난 후 목록 표시 방식 (지난 모임 분리 여부)
- 참석 관리 기능을 2단계 최우선 후보로 둘지 확정 필요

## 12. 2단계 후보

- 참석 관리: 참석, 불참, 미정 응답과 집계, 정원과 대기자 관리
- 정산: 비용 입력, 1인당 금액 계산, 송금 여부 확인
- 정기 모임 반복 일정
